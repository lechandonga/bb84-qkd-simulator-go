# BB84 量子密钥分发模拟器（Go，进程内本地模拟）

本仓库在**单个进程内**用模拟的光量子信道跑完整的 BB84 协商流程，并附带密钥
生命周期管理组件。噪声、丢包、窃听全部由本地配置 + 随机种子模拟，**不依赖任何
外部服务或真实设备**，同一配置重复运行结果逐位一致、可复现。

## 目录结构

```
internal/qkd/        BB84 协议核心
  config.go          可注入的信道与安全参数（噪声/丢包/窃听/种子/门限…）
  rng.go             带种子的确定性随机源（SplitMix64），全程串行使用
  protocol.go        态制备→信道→测量→基矢比对→筛选→抽样→纠错→保密放大
  cascade.go         CASCADE 信息和解（经典奇偶交互 + 二分定位 + 级联回溯）
  bits.go            二元熵 H2 与 Toeplitz 通用哈希（隐私放大提取器）
  errors.go          五类可区分的会话中止原因
  result.go          协商统计、密钥材料与确定性密钥 ID
internal/keystore/   密钥生命周期与并发消费语义
cmd/qkd-demo/        本地演示入口（多场景 + 并发申领）
```

## BB84 协商流程

1. **态制备（Alice）**：对每个光子随机选择比特与基（直线基 `+` / 对角基 `x`）。
2. **模拟量子信道**：光子按发送顺序串行经过
   - 丢包：按 `LossRate` 概率直接丢弃，接收端无记录；
   - 窃听（`Eavesdrop=true`）：Eve 对未丢失光子拦截-测量-重发。Eve 选错基时
     重发态在 Bob 基正确的情况下仍以 50% 概率出错，因此全程窃听会在筛选密钥中
     注入约 25% 的误码率；
   - 噪声：按 `NoiseRate` 概率对比特翻转。
3. **测量（Bob）**：独立随机选基；基一致时测得到达比特，基不一致时结果随机。
4. **基矢比对与筛选**：双方在模拟经典公共信道上公布所选基，只保留基一致的比特。
5. **抽样与安全判定**：按 `SampleFraction` 用种子确定性抽取位置，公开比对估计
   QBER（量子误码率），随后按门限与样本量判定（见下）。抽样比特被公开并剔除。
6. **纠错（CASCADE）**：分块交换奇偶校验，发现不一致则二分定位并翻转错误比特，
   并向历史轮次级联回溯。每轮块大小按 `k1≈0.73/QBER、2k1、4k1…` 调度；
   超过 `CascadePasses` 仍有残余误码则判定纠错失败。
7. **保密放大（Privacy Amplification）**：用 Toeplitz 矩阵做通用哈希提取，
   最终长度按 BB84 成钥率公式收缩：

   ```
   L = floor( n * (1 - H2(QBER)) - leak )
   ```

   其中 `n` 是抽样剔除后的协商比特数，`leak` 是纠错阶段实际发生的奇偶校验
   交互比特数。误码率越高、纠错泄露越多，最终密钥越短；收缩到 0 则中止。

## 误码率判定与会话中止

抽样 QBER 与 `QBERThreshold`（默认 `0.11`）比较，并给出**可区分的中止原因**：

| AbortReason             | 触发条件                                     |
| ----------------------- | -------------------------------------------- |
| `eavesdrop_suspected`   | 开启窃听且抽样 QBER 超过门限（疑似窃听）      |
| `qber_exceeded`         | 无窃听但自然噪声导致 QBER 超过门限            |
| `insufficient_sample`   | 抽样数 < `MinSampleSize`（如丢包过多）        |
| `correction_failed`     | CASCADE 在限定轮数后仍未完全纠正残余误码       |
| `zero_length_key`       | 保密放大后成钥长度收缩为 0                     |

任何中止都**不会产出密钥材料**：中止会话只登记一条 `aborted` 记录，对其申领
一律返回 `ErrKeyAborted`。门限内的正常噪声（默认配置下 `0~0.08` 均验证）不会
被误判为窃听。

## 确定性与可复现性

- 所有随机事件（制备、测量基、丢包、窃听、噪声、抽样位置、纠错排列、提取器系数）
  都来自同一个由 `Seed` 初始化的确定性随机源；
- 模拟严格按光子发送顺序**串行**推进，没有 goroutine 参与协议过程，因此结果
  不受并发或执行顺序影响；
- 密钥 ID 是对「种子 + 密钥内容 + 长度」的 SHA-256 截断，Alice 与 Bob 各自
  独立计算也必然得到相同的 ID 与长度。

## 密钥状态语义

| 状态        | 含义                                                     |
| ----------- | -------------------------------------------------------- |
| `available` | 协商成功，等待申领                                        |
| `consumed`  | 已被唯一一次成功申领取走，不可重复发放                     |
| `revoked`   | 被管理方主动作废，申领返回 `ErrKeyRevoked`                |
| `aborted`   | 会话因安全原因中止，不含任何密钥材料，申领返回 `ErrKeyAborted` |

`keystore.Store` 用互斥锁保证申领原子性：**并发申请同一份密钥时恰好一个成功**，
其余请求得到 `ErrKeyAlreadyUsed`；未知 ID 返回 `ErrKeyNotFound`；重复登记返回
`ErrKeyDuplicate`。重复或乱序申请不会改变或错配任何密钥内容。

## 本地验证

```bash
go build ./...          # 编译
go test ./... -v        # 运行全部单测（日志含业务域/用例与统计）
go test -race ./...     # 并发安全（需要 CGO）
go run ./cmd/qkd-demo   # 多场景演示：正常/噪声/丢包/超限/样本不足/窃听/并发申领
go run ./cmd/qkd-demo -seed 42   # 换种子；相同 seed 两次输出完全一致
```

测试日志以「业务[xxx] 用例=…」格式打印覆盖的业务域与每条用例的关键统计
（发送/丢失/基矢匹配/QBER/纠错比特数/最终密钥长度等），覆盖：

- 正常协商（低噪声、中等噪声、高丢包）与最终密钥逐位一致；
- 同配置可复现、不同种子产生不同密钥；
- 误码率上升时密钥长度单调收缩；
- 窃听判定中止、误码率超限、样本不足、纠错失败四类可区分中止；
- 正常噪声不被误判；
- 密钥状态流转、重复消费拒绝、64 路并发申领恰好 1 个成功、双端 ID/长度/内容一致。
